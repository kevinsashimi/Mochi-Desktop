Mochi Desktop updates — version 1.1.6
Verified 4 October 2026 (Asia/Singapore).

Confirmed Windows failure and fix:
- The user report from diagnostic 1.1.4.1 identified MissingMethodException:
  System.String.TrimEnd(Char), in the updater's temporary-directory validation.
- Mono runtime assemblies exposed an overload absent from Windows .NET Framework.
- Both calls explicitly use char[] now. Cloud compilation uses Microsoft's .NET
  Framework 4.8 reference assemblies, not Mono implementation assemblies.
- The compiler references are the official net48 NuGet package 1.0.3, verified by
  its catalog SHA-512. Reusable cloud setup includes these references.
- The compiled-signature regression rejects published 1.1.5 and accepts 1.1.6.

Behavior:
- Check for updates and automatic checks pin metadata and Mochi.exe to one GitHub commit.
- Consent precedes executable download; size, SHA-256, identity and version are verified.
- The current app stays running until its helper starts; the helper waits for that
  exact parent process to exit, replaces only Mochi.exe, and restarts the new app.
- Settings and startup shortcuts are preserved; a failed restart restores the old app.
- Failures show the exact stage, underlying exception/HRESULT and native error code.
- update-error.txt is saved beside preferences, falling back to LOCALAPPDATA\Mochi.
  Reports are local only. A failed report write does not hide the update error.
- Info shows the running executable path to distinguish copied installations.

Validation:
- All 22 groups passed: 10 companion, 7 updater, 5 Playful Mode.
- Existing update comparisons, pinned downloads, invalid metadata/payloads, cancellation,
  rollback, locked/changed targets, real helper wait/replacement/restart and UI menus pass.
- Added exact failure stages, report fallback, blocked launch preserving app/settings,
  temporary-directory acceptance/rejection and emitted char[] overload verification.
- Microsoft reference-assembly compilation establishes the API surface; Wine runtime
  checks do not replace a live Windows check of the fixed build, which remains pending.

Older affected builds require a one-time manual replacement of Mochi.exe because
those executables supply the broken helper. Keep settings.xml and Project Files.
See UPDATE-DIAGNOSTICS.md for installation steps and the confirmed root cause.
